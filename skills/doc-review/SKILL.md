# 文書品質レビュー

ビジネス文書（提案書、報告書、議事録、仕様書など）を、4つの評価軸に沿って批評するスキル。指摘と修正案を返す批評タスクであり、指示なく文書全体を書き直さない。

## 対象の特定

- ファイルパス、貼り付けられたテキスト、または Artifact/Notion ページの URL などレビュー対象を特定する。
- 対象が指定されておらず文脈からも推測できない場合は、どの文書をレビューするか確認する。
- 要約や一部だけでなく、文書全体を読んでから評価する。

## 評価軸

以下の4軸すべてについて評価する。各指摘には該当箇所の引用を添える。該当箇所がない項目は「問題なし」として良い。文脈と無関係な一般論は書かない。

### 1. 目的とターゲットの明確性
- 文書の目的（何のための文書か）と対象読者が明確か。
- 読者が次に取るべきアクション（ネクストアクション）が提示されているか。
- 読者が理解するために必要な前提知識や背景が共有されているか。

### 2. 論理構成とMECE（漏れなく・ダブりなく）
- 情報の抜け漏れ、または不必要な重複がないか（MECEの原則）。
- 結論や最重要情報が最初に提示されているか（結論ファースト）。
- 見出し（大・中・小）の階層が論理的であり、情報の粒度が揃っているか。

### 3. 文章の簡潔性と正確性
- 1つの文に複数の意味が詰め込まれておらず、短く簡潔か（一文一義）。
- 主語と述語のねじれがないか。修飾語がかかる先が明確か。
- 事実（データ・仕様）と、推測（意見・感情）が明確に区別されているか。
- 曖昧な表現（〜のようです、〜かもしれません等）が排除されているか。

### 4. 視覚的な読みやすさとフォーマット
- 3つ以上の並列要素や手順に対して、箇条書きや番号付きリストが活用されているか。
- 表記ゆれがなく、用語が統一されているか。

## 出力形式

軸ごとに、指摘があれば以下を示す。

- 該当箇所（見出し名 or 短い引用）
- 具体的な問題点
- 修正案（「もっと明確に」のような抽象的な指示ではなく、書き換えた文章や見出しそのもの）

最後に、総合判定（そのまま送れる／要修正）と、複数の軸で問題がある場合は最も優先すべき修正点を1つ示す。

レビュー結果の引用・修正案は文書自体の言語に合わせる（日本語文書なら日本語で書き換える）。

## 制約

- 明示的に依頼されない限り、文書全体の書き直しは行わない。指摘と修正案の提示に留める。
- 上記4軸の範囲外の要求（デザイン、事実確認など）を勝手に追加しない。
